# Rails 基本構成ハンズオン（ステップバイステップ）

このリポジトリを使い、**手元で動かしながら** Rails の基本構成と規約を学ぶ手順書です。  
所要目安: 60〜90分（飛ばし読み可）。

---

## このハンズオンで身につくこと

1. Rails アプリの標準ディレクトリの役割
2. リクエストの流れ **Route → Controller → View**
3. Model / Migration によるデータの永続化
4. 手書きの最小 CRUD（Memo）
5. 命名規約とファイル配置の対応
6. scaffold 相当のフル REST（Post）の見方

---

## 事前準備

### 必要なもの

- Ruby 3.2 前後
- Bundler
- SQLite3（開発用ライブラリ含む）

バージョン確認:

```bash
ruby -v
bundle -v
sqlite3 --version
```

### リポジトリを用意する

```bash
git clone <このリポジトリのURL>
cd <リポジトリ名>
git checkout cursor/rails-minimal-basics-e421   # 学習用ブランチ
# または main にマージ済みなら main でOK
```

### アプリを起動する

```bash
bundle install
bin/rails db:prepare
bin/rails db:seed
bin/rails server
```

別ターミナルで疎通確認:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/up
# → 200 ならOK
```

ブラウザで http://localhost:3000/ を開き、トップに Memo / Post へのリンクが見えれば準備完了です。

> **止め方**: サーバ起動中のターミナルで `Ctrl+C`

## Step 2 — Memo（手書き最小 CRUD）を動かす（15分）

Memo は「必要な部品だけ手でつないだ」例です。

### 2-1. ルートを確認する

```bash
bin/rails routes -g memo
```

期待される対応:

| HTTP | URL | アクション |
|------|-----|------------|
| GET | `/memos` | `memos#index` |
| POST | `/memos` | `memos#create` |
| DELETE | `/memos/:id` | `memos#destroy` |

`config/routes.rb` では次のように **使うアクションだけ** に絞っています。

```ruby
resources :memos, only: %i[index create destroy]
```

### 2-2. モデルとテーブルを確認する

| 見るもの | パス |
|----------|------|
| モデル | `app/models/memo.rb` |
| マイグレーション | `db/migrate/*_create_memos.rb` |
| スキーマ | `db/schema.rb` の `memos` |

コンソールで件数を見る:

```bash
bin/rails runner 'puts Memo.count'
```

### 2-3. 画面で CRUD する

1. http://localhost:3000/memos を開く
2. タイトルを入れて作成する
3. 一覧に増えることを確認する
4. 削除して減ることを確認する

### 2-4. コード対応を追う

| 操作 | 主に動くファイル |
|------|------------------|
| 一覧表示 | `MemosController#index` → `app/views/memos/index.html.erb` |
| 作成 | `MemosController#create` → 成功時 `redirect_to memos_path` |
| 削除 | `MemosController#destroy` |

### チェック

- [ ] Memo は 3アクションだけだと説明できる
- [ ] 画面操作とコントローラのメソッド名を対応づけられる

## Step 4 — Post scaffold を単位ごとに追う（25分）

Post は「規約どおりに一式そろった」例です。  
`docs/02`〜`06` を順に開きながら、実ファイルを確認します。

### 4-1. Model + Migration（docs/02）

見るファイル:

- `app/models/post.rb`
- `db/migrate/*_create_posts.rb`
- `db/schema.rb` の `posts`

確認コマンド:

```bash
bin/rails runner 'puts Post.column_names.inspect'
# => ["id", "title", "body", "created_at", "updated_at"] など
```

### 4-2. RESTful ルート（docs/03）

```bash
bin/rails routes -g post
```

7行（index/create/new/edit/show/update/destroy）出ることを確認します。  
`resources :posts` の **1行** がこれらを生やしています。

### 4-3. Controller（docs/04）

ファイル: `app/controllers/posts_controller.rb`

| メソッド | 役割 |
|----------|------|
| `index` | 一覧 |
| `show` | 詳細 |
| `new` | 新規フォーム |
| `create` | 保存 |
| `edit` | 編集フォーム |
| `update` | 更新 |
| `destroy` | 削除 |

`set_post` と `post_params` の private メソッドにも目を通します。

### 4-4. index / show / `_post`（docs/05）

| ファイル | 規約 |
|----------|------|
| `app/views/posts/index.html.erb` | `#index` の既定ビュー |
| `app/views/posts/show.html.erb` | `#show` の既定ビュー |
| `app/views/posts/_post.html.erb` | `render @post` が探すパーシャル |

### 4-5. new / edit / `_form`（docs/06）

| ファイル | 規約 |
|----------|------|
| `new.html.erb` / `edit.html.erb` | それぞれのアクション用 |
| `_form.html.erb` | `render "form"` で共有 |

ポイント: `form_with model: post` は、未保存なら POST（create）、保存済みなら PATCH（update）になります。

### 4-6. 画面でフル CRUD する

1. http://localhost:3000/posts を開く
2. 「新規」から記事を作成 → 詳細に遷移することを確認
3. 編集して更新
4. 削除して一覧に戻る

### チェック

- [ ] `resources :posts` と 7アクションの対応が説明できる
- [ ] `_form` が new/edit で共有されている理由が言える
- [ ] Memo（3アクション）と Post（7アクション）の違いが言える
